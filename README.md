# QSC 앱 (모바일 웹앱)

`QSC·MS 평가표.xlsx`(`1. QSC\3. 평가표\`)의 평가 로직을 옮긴 매장·본사용 모바일 앱(PWA · GitHub Pages)과
구글 앱스 스크립트 백엔드(`backend/Code.gs`). **엑셀 평가표가 문항·채점 기준의 원본**이다.

- 상태 정본: `1. QSC\현재상황.md` (이 README 보다 그쪽이 최신이다 — 다르면 그쪽이 이긴다)
- 연동 설정값(시트·스크립트 ID 등): `1. QSC\4. 스프레드시트\연동_설정값.md` — ★비공개 · 이 저장소에 올리지 않는다★
- 10월(2026-10-01)부터 26개 매장 실사용

## 문항은 서버가 내려준다 (2026-09-18)

- 공개 `data/master.json` 에는 문항이 없다. 문항은 `backend/Code.gs` 끝의 `QUESTIONS` 블록과
  `data/questions.local.json`(저장소 제외 · 도구용)에 있고, 둘 다 `tools/extract_master.py` 가 만든다.
- QSC 문항은 로그인 + qsc 권한이 있어야(`config.questions`), MS 문항은 살아 있는 제출 코드가 있어야(`survey.questions`) 내려간다.
- 그래서 **평가표 엑셀을 고치면 앱 배포와 백엔드 배포가 둘 다 필요하다**(release.py 가 끝에 알린다).

## 배포 — 두 갈래뿐

| 무엇 | 방법 |
|---|---|
| 앱 (GitHub Pages) | `배포.bat` = `tools/release.py` — 추출·QR·캐시 버전(?v=·sw.js VER)·push·실서버 대조까지 한 번에. `release.py check` 는 점검만 |
| 백엔드 (앱스 스크립트) | `백엔드배포.bat` = `tools/deploy_backend.py` — clasp 로 ★기존 배포를 갱신★한다(주소 그대로). 실서버 `?ping=1` 버전까지 대조 |

- ★script.google.com 에 새 프로젝트를 만들거나 Code.gs 를 손으로 붙여넣거나 `js/api.js` 의 서버 주소를 바꾸지 말 것★ —
  스크립트 속성(시트 ID·토큰 키 등)과 배포 주소가 끊겨 모든 요청이 실패한다.
- 버전 숫자(?v=·sw.js VER·ping 버전)는 손으로 올리지 않는다 — 배포 도구가 올린다.
- 배포 전 저장소에 남은 변경이 함께 올라간다(`git add -A`) — 먼저 `git status` 로 확인할 것.

## 채점 규칙 (평가표 엑셀 `QSC·MS 평가표.xlsx` 수식과 같은 값 — 2026-09-22 일반 문항 배점 변경)

- 일반 문항(58개): **1건 = 100 ÷ 해당 일반 문항 수** (해당 = NA 가 아닌 일반 문항 · 58개 모두 해당하면 1.72점 · 같은 문항 여러 건은 건마다 · 영역 구분 없음)
  - 2026-09-22 전에는 1건 = 1점이었다(팀장 승인으로 변경 — 58문항을 100문항처럼 빼서 후했고, NA 가 많을수록 유리했다)
- ★ 중대운영(12개): **문항당 −8, 같은 문항 추가 건당 −2, 합계 상한 −45** (단독 최저 등급 '주의')
- ★★ 즉시위해(4개): **문항당 −12, 같은 문항 추가 건당 −4, 합계 상한 −48** (단독 최저 '부적합')
- **QSC 점수 = MAX(0, 100 − 일반 감점 − 중대 차감)**, 소수 첫째 자리 반올림 (엑셀 D89 `ROUND(…,1)` · 등급도 반올림한 점수로)
- **종합점수(통합시트) = QSC×60% + MS×30% + 개선율×10%** (중대는 QSC 안에서 이미 빠졌으므로 다시 빼지 않는다)
- 등급: **우수 ≥93** / 양호 ≥85 / 보통 ≥76 / 미흡 ≥66 / 주의 ≥55 / 부적합 <55
- NA = 채점 제외 — 일반 문항은 NA 만큼 해당 문항 수(분모)가 줄어 1건의 무게가 커진다(해당 문항 중 어긴 비율이 같으면 점수도 같다)
- MS: 관찰 문항 예(1)/아니오(0) + 만족도 5점 척도(1점=0 … 5점=1 환산), 점수 = 환산 합계 × 100 ÷ 응답 수 (곱을 먼저 — 반올림 경계에서 엑셀과 같게).
  한 매장 한 달 1회이고, 실수로 2건 이상이면 제출시각이 가장 늦은 1건을 쓴다(평균 아님)

## 제출 한 번에 기록되는 곳

1. **응답 시트(QSC관리자 시트)** — QSC_회차·QSC_상세·MS_상세 등 원장
2. **[감사총무팀_QSC]통합시트** — 매장 행 × 해당 월 칸에 점수
3. **매장별 QSC현황 파일** — 월 탭(YYMM)에 방문일·점수·개선요청사항 표(탭이 없으면 첫 제출 때 그때의 원본으로 만든다)

잘못 낸 제출은 「관리자 도구 → 제출 관리 → 제출 되돌리기」로 지운다(월 탭은 지우지 않고 빈 양식으로 남긴다).
