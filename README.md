# QSC 앱 (모바일 웹앱)

`QSC 평가 체계 개편_v3.xlsx`(v3.12)의 평가 로직을 그대로 옮긴 모바일 입력 앱.
**엑셀 시트가 문항·채점 기준의 원본**이고, 앱은 입력·저장·집계를 자동화한다.

## 구성

| 경로 | 역할 |
|---|---|
| `index.html` | **홈(런처)** — GLOW SEOUL 브랜드 화면, 3개 메뉴로 진입 |
| `qsc.html` | QSC 점검 (관리자) — 74문항 개선 필요 건수 입력, 문항별 사진, 실시간 감점 집계 |
| `shopper.html` | 미스터리쇼퍼 평가표 (관리자) — 종이 응답 옮겨 입력용. 설문지와 **구조 동일** + 점수·집계·초기화 |
| `survey.html` | 미스터리쇼퍼 설문지 (**고객용**) — 쇼퍼가 직접 응답(서브폰 전달/QR). 점수·등급·집계 완전 비노출, 전 문항 필수. QR은 `survey.html?store=매장명` |
| `js/shopper-core.js` | **두 쇼퍼 화면의 공통 코드** — 안내문·문항·비고칸이 항상 동일하게 유지된다. `initShopperForm({admin:true/false})`의 admin 분기로만 점수·집계·초기화가 켜진다. 쇼퍼 화면 수정은 반드시 이 파일에서 (개별 수정 금지) |
| `data/master.json` | 문항 마스터 (엑셀에서 추출 — 문항·심각도·감점 파라미터·매장 목록) |
| `js/scoring.js` | 채점 엔진 — 절대 감점제, `test/test.html`로 검증(40개 테스트) |
| `js/api.js` | 저장 계층 — URL 비었으면 모의 저장(localStorage), 넣으면 구글 연동 |
| `js/qsc-app.js` | QSC 점검 화면 로직 |
| `js/ui-time.js` | **방문 시간 드롭다운(시·분)** — QSC·쇼퍼 공통 부품. 저장 형식 `HH:MM`, 분 5분 단위 |
| `js/ui-photo.js` | **사진 첨부 공통 부품** — 긴 변 1280px + **한 장 180KB 용량 상한**(품질을 낮춰가며 재인코딩, 안 되면 해상도 한 단계 축소). QSC 문항 증빙과 쇼퍼 영수증이 같은 규격 |
| `backend/Code.gs` | 구글 앱스 스크립트 백엔드 (시트 저장 + 드라이브 사진 업로드) — v3.12 스키마 |
| `tools/extract_master.py` | 엑셀 → master.json 재추출 (엑셀 문항 수정 시 실행. ★★4·★12 검증 내장) |
| `tools/make_qr.py` | 매장별 설문 QR 생성 → `data/qr.json`. **매장이 바뀌면 extract_master.py 다음에 실행** (`pip install segno`) |
| `codes.html` / `js/codes-app.js` | **제출 코드 관리 (관리자)** — 매장별 코드 발급·QR·현황판. 설계: `../_설계/쇼퍼_제출코드_설계.md`. **지금은 미리보기(모의)** — 구글 연동 시 저장소만 교체 |
| `manifest.json` / `sw.js` / `icons/` | PWA — 홈 화면 설치, 오프라인 실행(네트워크 우선 + 캐시 폴백) |
| `fonts/` | 나눔스퀘어 woff2 4종(L/R/B/EB) — 기기·오프라인 무관하게 동일 서체 |

디자인은 GLOW SEOUL 로고 기반 블랙&화이트 모노톤. 쇼퍼 응답은 관리자 입력/고객 직접 모두 같은 '쇼퍼_응답' 시트에 저장되고 '입력경로' 열로 구분된다. **개선현황 10%는 앱에 넣지 않고** 기존처럼 구글시트에서 직접 관리한다 (2026-08-10 결정).

편의 기능: 감점식(전 문항 0건·100점 시작), [이상 없음/NA] 버튼 + 건수 스테퍼, 건수 직접 입력(숫자 탭), 개선 필요 시 사진 유도, 감점 3층 집계·개선 필요 목록, 전체 초기화, **매장별 NA 자동 기억**(제출 시 저장 → 다음 회차 매장 선택 시 적용 제안, 연동 후엔 서버 'NA프리셋' 시트 우선).

## 로컬 미리보기

```
cd qsc-app
python -m http.server 8123
```
→ 브라우저에서 http://localhost:8123 (홈) / qsc.html / shopper.html / survey.html / test/test.html (엔진 검증)

## 채점 규칙 (엑셀 v3.12와 동일 — 절대 감점제)

- 일반 문항(58개): **1건 = −1점** (영역 구분 없음, 상한 없이 누적)
- ★ 중대운영(12개): **문항당 −8, 같은 문항 추가 건당 −2, 합계 상한 −45** (단독 최저 등급 '주의')
- ★★ 즉시위해(4개): **문항당 −12, 같은 문항 추가 건당 −4, 합계 상한 −48** (단독 최저 '부적합')
- **QSC 점수 = MAX(0, 100 − 일반 감점)** — ★/★★는 평균에 넣지 않고 차감액만 집계
- **최종점수(통합시트) = QSC×60% + 쇼퍼×30% + 개선현황×10% − 중대 차감** (하한 0)
- 등급: **우수 ≥93** / 양호 ≥85 / 보통 ≥76 / 미흡 ≥66 / 주의 ≥55 / 부적합 <55
- NA = 채점 제외 (문항 점수가 서로 독립이라 가중치 재분배 없음)
- 쇼퍼: 관찰 30문항 예(1)/아니오(0) + 만족도 10문항 5점 척도(1점=0 … 5점=1 환산, NA 불가), 점수 = 환산 합계 ÷ 응답 수 × 100

## 구글 연동 (배포 시) — 제출 1번에 3곳 기록

`backend/Code.gs`가 제출 한 번에 다음을 모두 기록한다 (v3.12 스키마, 배포 대기):

1. **응답 원본 시트** (QSC_회차: QSC점수·감점 3층·중대차감 / QSC_상세: 코드·등급구분·감점 / 쇼퍼_응답·쇼퍼_비고) — 추적용 원장
2. **통합시트 [데이터]** — 매장 행 x 해당 월 블록에 점수 기입 (QSC→위생 칸, 쇼퍼→CS 칸, 0~1 소수로 변환. 같은 달 쇼퍼 여러 명이면 월 평균). ⚠위생 칸에는 QSC 점수(중대 차감 전)가 들어가므로, **중대 차감은 통합시트 최종 수식 교체 때 반영해야 함**
3. **매장별 QSC현황 파일** — 월 탭(YYMM)에 방문일·점수 기입 + 개선 필요 문항(1건 이상)을 개선요청 표에 자동 행 추가 ([★★/★ 중대] 표기 + 코드 + 건수 + 사진) → 기존 개선율 집계 수식이 그대로 살아서 통합시트 개선율까지 자동

배포 절차:
1. 응답 저장용 스프레드시트 + 사진 폴더(드라이브) 생성
2. **통합시트 안에 '매장파일맵' 탭 생성** (A열=매장명, B열=해당 매장 QSC현황 파일 ID)
3. script.google.com 새 프로젝트에 `backend/Code.gs` 붙여넣기, 상단 ID들 입력
4. 배포 → 웹 앱 (실행: 나 / 액세스: 모든 사용자) → URL을 `js/api.js`의 `APPS_SCRIPT_URL`에 입력

주의: PHOTO_EMBED=true면 개선요청 표에 사진이 =IMAGE()로 보이는 대신, 사진 파일이 '링크 있는 사용자 보기' 공유로 바뀜 (내부 링크 공유 수준).

## 대시보드(구글시트)와의 동기화 원리

- **앱 → 시트 (업데이트)**: 제출 즉시 위 3곳에 기록
- **시트 → 앱 (따라가기)**: 앱이 열릴 때마다 백엔드 `?action=config`로 통합시트의 현재 매장 목록(숨김 행 제외)을 실시간 조회. 시트에서 매장 추가·숨김·이름변경 → 앱 다음 실행 때 자동 반영. 오프라인이면 마지막 성공 캐시, 연동 전이면 master.json 저장본
- **평가표(74문항)는 로컬 엑셀이 원본** — 문항·심각도·감점 변경 시 `tools/extract_master.py` 실행 + 4개 html `?v=N`·sw.js 버전 인상
- 대시보드 **구조 자체**(월 블록 열 위치, 매장 행 시작 등)가 바뀌면 Code.gs 매핑 수정 필요 — 구조는 고정 권장
